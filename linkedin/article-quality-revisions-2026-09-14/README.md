### Corrections worth highlighting

- A pre-write authorization read does not by itself close a time-of-check/time-of-use race.
- The model specifies **expiry at admission**, not “no commit after expiry.” Distributed revocation remains outside its scope.
- A timeout can follow a successful commit. A bounded retry is safe only under the receiving domain's specified contract.
- An outbox can bind one domain's mutation and outgoing event, not every downstream business effect.
- In Q3 the 80% probability is **timely end-to-end interception among all high-impact errors**, not recall only within the reviewed subset. This sharpens the earlier audit's shorthand: routing 80% of relevant errors and timely detection of 80% of those yields 64%, hence nine expected escapes, not five.
- In Q4 the old-rule scenario gives 80 handling hours over 15 working days. With candidate error rate 1% versus old rate 4%, the comparable potential reduction is 60 hours. Neither establishes cash savings.
- The CRM McKinsey link now serves the August 25, 2026 survey. The draft uses its 37% enterprise-EBIT response figure with a date and survey limitation instead of retaining unsupported 2025 figures under that changing link. Gartner's 2025 projections remain explicitly forecasts.

## Reproduce and validate

Run from this directory, using Python 3.9+ and Node with `marked` and `sharp` available:

```sh
python3 -m unittest -v test_protocol test_calculations
node build_review.mjs
python3 validate_review.py
```

The build uses the installed Codex desktop Node dependency directory by default. Set `CODEX_NODE_MODULES` to a directory containing `marked` and `sharp` on another machine. No dependency is installed or downloaded by the script.

Tests use isolated temporary SQLite databases. Never point the teaching model at a production database or reuse its fixture setup against valuable data. It creates synthetic tables and is not an IAM service or CRM adapter.

### Test coverage and boundaries

- 16 protocol tests: atomic commit/outbox, lost response, connection restart, concurrent duplicate workers, changed intent, approval reuse, wrong identities, expiry boundary, stale record, policy change, revocation ordering and injected outbox failure.
- 8 calculation tests: escape model, conditional two-stage detection, sensitivity, workload/counterfactual, bad-rule cost, zero-event bound and invalid inputs.
- Package validation: generated-content hashes, local assets/links, retained CRM lists and eight unchanged figures, source baseline hash, Python/JSON article snippets, no script/form injection and explicit not-applied state.

The model has no external calls, authentication, signature verification, policy-distribution protocol, deduplication expiry mechanism, production load test or end-to-end CRM integration. Operation scope is implicit because it supports one operation. The outcome lookup is an unprotected teaching read and requires separate authorization in a real service. The no-contract branch tests a policy selector, not a remote implementation.

The arithmetic tests validate calculations, not the evidence for assumed inputs. The 2.95% zero-failure bound requires the stated independent-binomial trial model and is not a production safety guarantee.
